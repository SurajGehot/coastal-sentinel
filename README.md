# Coastal Sentinel

Coastal Sentinel is an unsupervised sonar-anomaly monitoring prototype. It
uses a Python API and a browser dashboard to review unusual acoustic returns
from an archived NOAA fisheries-sonar recording.

> **Important limitation:** The NOAA recording is unlabeled 18 kHz
> water-column sonar. It has no verified ghost-net or marine-debris examples.
> The model flags statistically unusual acoustic patterns; it does not
> identify debris or demonstrate debris-detection accuracy. The dashboard
> replays a held-out portion of the archive and is not connected to a live
> sonar instrument.

## Features

- Four dashboard pages: Overview, Detection Review, Transect Monitor, and
  Model Health.
- A Python FastAPI service streams archived test pings to the browser.
- An scikit-learn Isolation Forest trained on derived sonar features.
- Chronological training, validation, and test partitions, with a 10-ping
  embargo between partitions.
- A saved model artifact and metadata generated by the training pipeline.

## Requirements

- Python 3.13
- Internet access for the initial NOAA dataset download
- Windows with PowerShell for the convenience commands below
- Node.js/npm only if using the npm command shortcuts

The application itself is Python and browser JavaScript; npm is only a
convenience command runner and is not used for machine learning.

## Run on Windows

Clone the repository and move into its directory:

```powershell
git clone https://github.com/<your-username>/coastal-sentinel.git
cd coastal-sentinel
```

Run the one-time setup. It creates `.venv`, installs `requirements.txt`,
downloads the NOAA recording, preprocesses and splits the data, and trains
the model:

```powershell
npm run setup
```

Start the application:

```powershell
npm start
```

Open [http://localhost:4173](http://localhost:4173). The dashboard replays
one held-out test ping every 1.2 seconds. Use **Pause stream** and
**Resume stream** to control playback.

### Run without npm

These commands perform the same setup and run directly through the Python
virtual environment:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m backend.download_data
.\.venv\Scripts\python.exe -m backend.train
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 4173
```

### macOS and Linux

The npm shortcuts use PowerShell and are intended for Windows. On macOS or
Linux, run the equivalent setup and start commands from the repository root:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m backend.download_data
.venv/bin/python -m backend.train
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 4173
```

Then open [http://localhost:4173](http://localhost:4173). If Python 3.13 is
not available as `python3.13`, install it and adjust the command accordingly.

## Retrain and test

After setup, retrain the model with:

```powershell
npm run train
```

Run the Python test suite with:

```powershell
npm test
```

Without npm, run the corresponding Python commands:

```powershell
.\.venv\Scripts\python.exe -m backend.train
.\.venv\Scripts\python.exe -m unittest discover -s tests_python -v
```

To restore the source recording without retraining, run `npm run setup:data`
on Windows, or `.\.venv\Scripts\python.exe -m backend.download_data` directly.
On macOS/Linux, use `.venv/bin/python -m backend.download_data`.

## Dashboard pages

| Page | Route | What it shows |
|---|---|---|
| Overview | `/` | Stream status and recent sonar readings |
| Detection Review | `/detections` | Flagged pings and explanation of alert meaning |
| Transect Monitor | `/transect` | Replay charts for anomaly scores and echo range |
| Model Health | `/model` | Model configuration, data splits, holdout alert rates, and limitations |

## Data and training

The source is NOAA NCEI cruise SH1305, Bell M. Shimada, recorded with a
Simrad EK60 at 18 kHz. Dataset details and provenance are in
[`data/README.md`](data/README.md). The downloader saves the archive to
`data/raw/noaa-sh1305-18khz.csv`.

[`backend/data.py`](backend/data.py) validates pings, filters invalid
backscatter samples, and derives six features: mean and spread of echo
intensity, strong- and weak-return ratios, peak-return range fraction, and
valid-sample coverage. [`backend/train.py`](backend/train.py) writes
chronological partitions under `data/splits/` and fits the Isolation Forest
using only the training partition.

The validation partition calibrates the alert threshold to a target 5% alert
rate. The held-out test partition is replayed by the site. Since the dataset
has no debris labels, reported rates are **unlabeled anomaly statistics—not
accuracy, precision, recall, or evidence of debris detection**. The generated
model and its metadata are saved under `models/`.

## API

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/api/health` | API, model, and replay status |
| `GET` | `/api/model` | Model metadata and holdout summaries |
| `GET` | `/api/history` | Recent replayed pings and aggregate metrics |
| `GET` | `/api/events` | Server-Sent Events (`sample`, `detection`, `stats`) |
| `POST` | `/api/stream/start` | Resume the held-out replay |
| `POST` | `/api/stream/stop` | Pause the held-out replay |

## Repository description

> Unsupervised sonar anomaly monitoring prototype for exploring unusual acoustic returns in coastal waters.

For real-world debris monitoring, connect a real sonar feed and validate the
model against independently verified, operator-reviewed debris observations.
